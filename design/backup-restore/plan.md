# 备份与恢复：减负方案

状态：已按本方案完成 Flutter 页面改造。2026-09-09。HTML 文件保留为设计参考；实际交互接入现有协调器。


最新收敛：按用户进一步减负要求，实际页面已移除首页介绍、保留份数提示、通用内容说明、时间记录和重复的流程解释。保留操作、备份数据、必要错误及覆盖确认；文件清单进一步改为立绘、图片、视频、音频、文档的分类数量，角色内同样汇总。下方为初版设计过程记录。

**首页只回答两件事：现在怎么备份、需要时从哪份恢复。** 沿用崽档的纸白、墨色与火漆红；把任务报告改为短暂反馈，把目录与统计改为按需查看。

## 现在为什么繁琐

现有页面同时展开本机资料统计、常驻任务报告、阶段列表、时间与文件统计、云端备份和多段说明。操作已经结束后，用户还要判断这些信息是否需要处理。

备份前再次展示资料清单并确认，恢复入口又叫“下载并检查这份备份”，让用户承担了流程拆分的理解成本。旧版备份、本机恢复前副本已经按此前要求移除，本方案不重新引入。

## 推荐页面

| 位置 | 显示内容 | 行为 |
| --- | --- | --- |
| 导航栏 | 备份与恢复、返回、刷新 | 沿用现有路由；刷新有无障碍标签 |
| 操作区 | 备份到 iCloud、一句说明、**立即备份** | 点一次开始；进行中原位换成短状态 |
| 云端列表 | 可恢复的备份；保留最近 3 份 | 每行仅日期时间、来源设备、大小、进入箭头 |
| 次要说明 | 备份包含哪些内容 | 默认折叠，解释已保存资料范围和非自动同步 |

不在首页展示本机各类数量、开始与结束时间、完整阶段清单、复用/上传统计、文件路径、校验结果。相关诊断保留在日志，需要用户处理的错误提供“查看原因”。不做自动备份开关，因为当前没有这一能力。

列表时间使用备份内容形成时间，详情补全年份；设备名与大小帮助判断备份来源。不要仅凭备份时间显示“已是最新”或“已同步”，它不能证明之后的本机修改已经备份。

## 两条交互路径

**备份：立即备份 → 简短进度 → 更新列表与完成提示。**

- 删除“这次会备份什么”的前置确认；备份不会替换本机资料。
- 有实际文件进度时显示当前文件的已处理量，并明确它的范围；无法计算整体进度时只显示当前状态，不拼装假百分比。
- 提交文件后仍需等待云端发布确认，此时显示“正在确认云端备份”，不能提前显示完成。
- 成功后用约 4 秒的“备份已完成”提示，再回到日常页面。辅助功能开启时延长提示；云端列表是持久的成功结果。
- 仅对本次观察到的任务完成事件提示一次，重新进入页面或重启不再弹出旧成功报告。失败、等待用户确认和清理问题各自处理，不按成功一起隐藏。

**恢复：选择备份 → 看概要 → 恢复这份备份 → 下载与检查 → 确认覆盖 → 恢复完成。**

- 详情优先展示时间、来源、角色数、文件数、大小。“查看备份内容”默认折叠，保留已有角色目录、文件清单、时间记录的查阅能力。
- “恢复这份备份”启动准备；按钮上方解释“下载并检查后，再由你确认替换本机资料”。准备期间不会更换本机数据。
- 检查成功才出现一次最终确认：“替换本机资料？”标明目标备份时间、设备与范围，并明确“本机现有的角色资料、设定历史、立绘和资产将被替换。恢复后无法撤销。”
- 默认焦点放在“暂不恢复”；最终“确认恢复”沿用项目的墨色确认样式。资料损坏、空间不足、版本不支持时不能进入此确认。
- 下载阶段支持现有安全取消；真正替换期间禁用返回与取消。不能用隐藏状态或换文案来掩盖实际卡死。
- 恢复成功后简短提示，回到正常页面。恢复中为防止半完成而保留的内部回滚机制照常工作，不向用户提供成功后的本机副本或撤销入口。

## 状态与边界

| 状态 | 用户看到什么 | 可做什么 |
| --- | --- | --- |
| 首次使用 | 立即备份；还没有云端备份 | 开始备份 |
| 正常 | 立即备份；简短云端目录 | 备份或查看某一份 |
| 读取列表 | 列表区域加载状态 | 有缓存时保留已知列表，避免整页抖动 |
| 本机统计未完成 | 操作区“正在准备资料” | 列表独立加载，不伪装为无备份 |
| 备份进行中 | 当前阶段和真实可测进度 | 仅在协调器允许时取消 |
| 等待发布确认 | 正在确认云端备份 | 保持等待，不能重复提交 |
| 下载与检查 | 正在下载并检查；本机资料不会被替换 | 安全取消；离开详情不会自动确认 |
| 准备完成 | 恢复确认；取消后保留“继续恢复”入口 | 确认或放弃；重进页面仍需明确确认 |
| 真正替换中 | 正在恢复资料；请保持 App 打开 | 禁止重复操作与不安全取消 |
| 长时间无进展 | 恢复耗时较长；可查看当前真实步骤 | 保持任务可观察，禁止猜测剩余时间 |
| 成功 | 短提示；列表成为持久结果 | 正常使用 |
| 失败 | 这次备份未完成；简短原因与重试 | 错误持续到解决或明确关闭；保留已有备份 |
| iCloud 不可用 | 检查账户和网络；重新检查 | 不把列表读取失败显示为“没有备份” |
| 本机无法打开 | 简短恢复引导；已有云端目录 | 禁止备份坏数据，允许恢复；沿用 recoveryOnly 限制 |
| 清理未完成 | 必要时一行“部分旧文件待清理” | 查看原因与重试；不能错误宣称空间已释放 |

“恢复耗时较长”应依据当前阶段持续时间、最后有效进展和实际错误判断，作为可观察性改进。原型不设生产超时承诺。若真正发生阻塞，应结合协调器和数据库切换日志修复；UI 动画不会解决卡死。用户此前反馈的切换阻塞已经另行修复，本次设计不能作为其性能验收。

## 视觉规则

- 纸白 `#FAF6F0`、墨色 `#2B2622`、火漆红 `#C2402A`；深色沿用现有 token。红色集中于当前主操作，不把每张备份做成抢眼卡片。
- 页面使用 24px 横向留白、8px 按钮圆角、细分隔线；一行清晰主标题，加一行辅助说明。不加装饰插画、数据仪表盘、渐变、玻璃效果和模拟手机边框。
- 保留原生中文系统字体：标题 26px，导航 17px，正文 14–16px，辅助 12–13px；按 Flutter 系统文字缩放适配。
- 原型浅色辅助文字加深至 `#72675E`，满足小字对比度；落地时先使用页面局部语义色，不扩大为未经评估的全局主题改动。
- 所有操作热区至少 44px；主按钮 52px。键盘焦点可见，弹窗焦点约束，取消为默认焦点。支持减少动态效果；有进度用数值，无进度用状态文本。

### 验收

- 首页点一次即可启动备份；不会因重复点击开启并发任务。
- 完成提示只在本次成功事件出现，重进页面没有旧完成卡；失败不会被误当作成功隐藏。
- 列表和概要来自该份备份的目录描述及 `contents.json`，不拿当前本机统计冒充；读详情不下载全部原文件。
- 下载与检查前后，本机数据保持不变；只有最终确认才执行激活。取消确认、重启、导航返回均不能绕过确认。
- 云端未确认发布前不显示成功；无法测量时不显示整体百分比。
- iCloud 错误、本机错误、未完成清理均有明确处理入口；无备份与读取失败是不同状态。
- 保留 recoveryOnly、发布时禁取消、激活时禁退出及原子回滚约束。
- 320 / 375 / 414 / 768px、深浅色、较大文字、键盘/屏幕阅读器均可操作；没有横向溢出和被截断的关键操作。
- Flutter 落地后运行页面测试、既有备份与存储核心测试及 analyze；真机验证备份、恢复、取消和中断后重新进入。当前 HTML 原型不能替代这些验收。

## 交付与原型边界

- `preview.html`：首页 / 详情 / 最终确认三屏总览。
- `prototype.html`：可点击，顶部切换首次备份、运行中、失败、iCloud 不可用、恢复耗时较长等状态；支持深色预览。
- `tokens.css` / `styles.css` / `app.js`：独立原型资源，无第三方依赖，无上传或真实数据读写。
- 示例：2026-09-09 14:32，iPhone，2 个角色、5 个文件、45.1 MB，来自本次已展示的备份元数据。模拟操作不会生成新的真实备份，演示时间不代表实际耗时。

Hallmark：Workbench 的原生工具页适配；沿用既有品牌，故不轮换主题；无视觉装饰。采用系统单字体是为了与 Flutter 页一致。品牌营销页专属的 hero、定价、社交证明、网站 footer 等检查不适用。页面按适用的克制、真实信息、对比度、交互状态与响应式要求验收，记录见 `verification.md`。
