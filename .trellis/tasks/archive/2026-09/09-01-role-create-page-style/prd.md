# 优化 RoleCreatePage 样式

## Goal

打开新建 / 编辑角色页时，第一眼是顶部铺满的 3:4 立绘 hero（这块就是立绘选择器，替代现在的 `140 × 186` 小图）。hero 下方的「基本信息」和「设定」分别收进纸面卡片，看起来像档案而不是一长串裸表单。字段、保存和选图逻辑不变。

## Background

`RoleCreatePage`（`lib/pages/role_create_page.dart`）同时承担新建和编辑：传入 `role` 为编辑。字段为立绘、名字、性别、年龄、生日、种族、身份、设定；编辑态可进设定修改历史。保存在 AppBar 右侧。入口是 `RoleListPage` 的 FAB（新建）和列表点击（编辑）。

现状：AppBar 下方居中固定 `140 × 186` 的 3:4 圆角立绘选择器，再往下是带小标题的裸表单（「基本信息」「设定」只是 13px 次要色文字，没有卡片容器）。输入框走全局 `InputDecorationTheme`（`lib/theme/zaidang_theme.dart`）。每个角色只有 `Role.coverImg` 一张本地图；`CoverImagePicker` 原图落沙盒，不裁切、不另存 banner。列表页用 56 方形缩略图。仓库里没有现成的档案卡片组件。

主题合同见 `.trellis/spec/frontend/theming.md`：纸白画布、墨色正文、火漆红只给保存等主操作；Card / 输入填充为 `surface` + `border`；除设定卡导出外只用 tokens + 系统控件。

近期相关提交：`49c531d` 接入崽档主题；`382fa04` 输入框改纸面描边；`ac1b49f` 重排创建页并加设定历史。

已拍板（本任务规划）：

- **立绘即 hero**：顶部一块 3:4 大图，既是 hero 也是立绘选择器。不叠独立横幅，不把同一张图裁两次。
- **沉浸式名片头图**：全宽 352pt 头图用同一张立绘做高斯模糊背景；左下角纸面名片放清晰的 3:4 小立绘（可带名字/种族·身份）。不用 Material AppBar，玻璃返回/保存，底部纸面圆角接到表单。
- **档案分组**：hero 下方用两块纸面卡片承载「基本信息」和「设定」，不是只加大标题。
- 卡片内仍用全局 `InputDecorationTheme`，不另做无描边行内输入。

## Requirements

- **R1** 创建 / 编辑页第一块是全宽沉浸式头图，高度约 352pt（对齐 memory 详情页媒体头），从屏幕顶部铺起，左右贴齐窗口边缘。表单栏（标题 + 卡片）另有宽度上限并居中，不把头图限宽。
- **R2** 头图背景是同一张立绘的高斯模糊（`ImageFiltered`）；左下角名片上是清晰 3:4 小立绘。点名片或背景仍走相册选图。无图时小立绘槽显示「添加立绘」。不新增第二张图字段。
- **R3** 不新增封面字段、不改 `CoverImagePicker` 落盘、不裁出第二张 banner。列表页 56 方形缩略图保持不变。
- **R4** 不用 Material AppBar。返回是玻璃圆形按钮；保存是玻璃胶囊，文字 `accent`，禁用 `inkSecondary`。头图铺整幅暗色渐变（`ZaidangTokens.dark.bg` 透明度），底部用纸色 `bg` 圆角盖接到表单。「新建角色 / 编辑角色」写在纸面内容区。禁止火漆红铺满顶栏。
- **R5** 基本信息与设定的字段集合、两列排布（性别/年龄、种族/身份）、名字必填校验、保存成功返回列表、编辑态「修改历史」入口与恢复回填，行为与现在一致。
- **R6** 颜色只来自 `ZaidangTokens` / `Theme.of(context)`。hero 空态填充用 `surface`，描边用 `border`，占位文字用 `inkSecondary`。卡片填充 `surface`、描边 `border`。亮色 / 暗色同一套版式。
- **R7** hero 下方恰好两块档案卡片，顺序为「基本信息」→「设定」。
  - 基本信息卡片：标题「基本信息」，内含名字、性别、年龄、生日、种族、身份。
  - 设定卡片：标题「设定」；编辑态标题行仍有「修改历史」；内含设定多行输入。
  - 卡片在纸色画布上左右留白（手机上 hero 贴边、卡片不贴边），圆角与现有输入框一致（8）。
  - 卡片内输入框继续用全局描边主题，不换成无边框分割行。

## Acceptance Criteria

- [ ] **AC1** 在约 390 宽的手机视口打开「新建角色」：头图全宽、高度 352、顶边贴齐屏幕（`top == 0`），空态可见「添加立绘」。没有 Material AppBar；返回是玻璃按钮，保存是玻璃胶囊。标题「新建角色」在头图下方纸面区。
- [ ] **AC2** 有立绘时（编辑已有封面，或新建选图后），同一块 3:4 区域显示该图（`BoxFit.cover`）。点按仍打开相册；取消选择则画面不变。
- [ ] **AC3** 宽窗口下头图仍全宽，但高度保持 352，不会按 3:4 拉满窗高。表单栏居中且有上限。
- [ ] **AC4** 「保存」为火漆红文字、在玻璃底上可读；保存中禁用态为次要墨色。返回按钮可把页面 pop 掉。
- [ ] **AC5** 名字留空点保存仍提示「请填写名字」且不落库；填名字保存后返回列表，编辑改名后列表更新。编辑页「修改历史」仍可打开并恢复设定到输入框。
- [ ] **AC6** 角色列表页外观与入口不变（FAB 新建、点行编辑、56 方形缩略图）。
- [ ] **AC7** 亮色画布为纸白，暗色为暖黑；hero 空态和卡片都不是冷灰或 Material 紫。现有 `test/widget_test.dart` 中与创建/编辑相关的用例在按手机视口调整后仍通过，并覆盖「贴边 3:4 hero + 添加立绘」以及「基本信息 / 设定」分组标题。
- [ ] **AC8** 「基本信息」字段（名字到身份）在一块可见的纸面卡片内；「设定」输入（及编辑态「修改历史」）在另一块纸面卡片内。两块卡片位于 hero 下方，彼此分开，背景为 `surface`、有 `border`。手机上卡片左右不贴齐屏幕（与贴边 hero 有反差）。

## Out of Scope

- 设定卡导出模板的像素级设计
- 增删角色字段，或改保存、校验、选图落盘、设定历史恢复逻辑
- 给角色加第二张图或从相册裁独立 banner
- 滚动折叠 / 视差 SliverAppBar（本次只做静态沉浸：图铺进顶栏，不随滚动缩小）
- 角色列表页、设定历史页的版式大改
- 第二套组件库、自定义插画、字体换新
- 把两列字段改成单列，或把基本信息再拆成更多卡片
- 卡片内改成无描边的设置行 / 分割线表单

## Risks

- Flutter 默认测试视口约 800×600；hero 按全宽 3:4 计算会很高，「添加立绘」可能落在 `skipOffstage` 之外。实现时测试应使用手机逻辑尺寸（与现有设定历史用例的 `390 × 1200` 同类）。
- macOS / iPad 窗口若忘记宽度上限，3:4 全宽会让页面不可用。AC3 就是为此设的。
- 3:4 hero 加上两块卡片后，手机上基本信息会在首屏以下。这是已接受的代价；不为此把 hero 裁成横幅。
- 卡片描边套着输入框描边会有一点双框。用卡片内边距消化，不为了去双框改输入主题。
