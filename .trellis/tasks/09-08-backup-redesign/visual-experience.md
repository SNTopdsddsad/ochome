# 备份与恢复：全链路可视化交互方案

2026-09-08 · 用户追加的明确要求：能看到备份了哪些数据、备份时间、备份进度与恢复进度。本文件补充原审核稿，仍处于设计审核，不代表已实现 Flutter 功能。

## 1. 用户应能回答的五个问题

1. 我这次准备备份哪些角色、设定、立绘和资产？
2. 当前进行到哪里了，正在处理什么，还需要多久？
3. 我上次成功备份是什么时候，内容反映的是哪个时间点？
4. 这份历史备份具体包含哪些角色和文件？
5. 恢复会替换本机哪些资料，哪些已经下载/检查/恢复，失败后我的资料是否还在？

信息默认显示摘要，可进入完整目录；不把内部随机文件路径、SQLite 表名、摘要串或技术日志当主要界面内容。只浏览目录不等于勾选范围；当前仍为完整备份、整份恢复。

## 2. 页面与导航

```text
备份与恢复总览
  ├─ 本机已保存资料 → 角色目录 → 该角色的资料种类和文件
  ├─ 备份前范围 → 正在备份 → 完成报告 → 这份备份详情
  ├─ 正在进行的任务 → 实时进度 / 等待 / 失败 / 重试
  └─ 云端备份记录 → 备份详情
                    ├─ 角色资料目录
                    ├─ 文件清单 → 单个文件信息
                    ├─ 时间记录
                    └─ 下载并检查 → 恢复前确认 → 数据切换 → 恢复报告
```

备份页面仍从档案页进入；不额外改动底栏或“我的”页。用户已取消手动文件备份，不提供导出完整备份文件、从文件恢复或旧「保存到文件」入口。

## 3. 页面内容合同

### A. 总览

- 本机已保存资料：角色数、设定修订总数、自定义属性总数、原始文件数、资料总量。
- 直达本机完整目录；统计来自一致的已保存数据快照。原始文件数不包含 database、manifest、目录索引和缓存。
- 上次成功备份：内容时间、来源设备、状态；“本机资料”与“云端已备份资料”分开展示。
- 进行中任务常驻入口：当前阶段、必要进度、等待/失败原因；离开页面后仍能回到同一任务。
- 云端记录列表：内容时间、来源设备、角色数、资料总量、可用/等待/检查失败状态。
- 发现中、无备份、未登录、离线和加载失败分别呈现，不都显示空列表。

### B. 备份前范围

完整列出：角色基础字段和设定、自定义属性及其顺序、设定历史、立绘原图、图片/视频/音频/文档各自数量与字节。

提供两个不同量纲：

| 信息 | 含义 |
|---|---|
| 完整资料总量 | 这份备份能还原多少资料，按逻辑资料统计 |
| 本次预计上传 | 当前缺少/变化对象和元数据所需传输量 |
| 已可复用 | 原文件数与字节；这些资料仍包含在完整备份中 |

示例原型：8 位角色、46 版历史、27 项属性、8 张立绘 + 78 份资产，共 86 份原文件，媒体 3.00 GB；新增 6 份媒体约 423.5 MB，加数据库约 2 MB，显示本次约 426 MB。其他 80 份媒体复用约 2.58 GB。这些仅为示例数据。

预览范围可以变化：点击“开始备份”取得确定快照后，要将“预计”替换为实际范围，并记录内容时间；禁止继续使用启动前过期的统计结果。

### C. 实时进度

备份步骤：生成资料快照 → 准备原始文件 → 上传变化内容 → 等待云端确认 → 完成。

恢复步骤：读取备份目录 → 下载原始文件 → 检查与升级资料 → 等待用户确认 → 切换本机数据 → 完成。

每个阶段可展示：

- 当前阶段名称，已完成/进行中/待执行状态。
- 本阶段已完成字节 / 本阶段总字节（有可信数据时）。
- 原始文件的已完成数量 / 总数；当前文件友好名称、所属角色、类型、大小。
- 任务开始时间、已用时；速度和剩余时间仅在采样充足时显示。
- 暂停、取消、失败原因、重试；按钮能力从 coordinator 状态提供，页面不自行猜测。
- 可展开文件处理列表：待准备、可复用、准备中、上传中、等待云端确认、已确认、下载中、校验中、校验通过、失败。

**不使用加权凑出来的“全流程百分比”。** 当上传 100% 时，只能标“本阶段传输完成”；如果云端确认尚未到达，标题仍是“等待云端确认”，不能出现整体成功。恢复下载 100% 也不能代替“已校验”“已恢复”。

若 iCloud 只提供完成状态而不提供可信的字节进度，显示“已确认上传 4 / 6 份”和等待状态，不按文件数伪造字节百分比。不知道速度/ETA 时留空或写“正在估算”；网络无进展时不让倒计时继续跑。重试如需重传，明确重传范围，允许本次尝试进度重新计算，不保留虚假 99%。

### D. 备份详情与内容浏览

固定三个视图：

- **角色资料**：该次备份内的角色名称；基础资料/完整设定是否包含；自定义属性数量及名称/顺序；修订数量；立绘与资产数量。进入角色可查看其文件明细。
- **文件清单**：备份时的显示名称、所属角色、类型、原始字节数；按角色分组和分页。后续本机重命名或删除不能改变历史目录。
- **时间记录**：内容时间、任务开始、创建者确认完成、耗时、来源设备，以及本机该次恢复的开始/检查/确认/完成时间（如有）。

完整历史字段正文、各版设定全文对比和媒体在线播放不是本次可视化的必需范围。按需浏览媒体内容可以沿用独立下载/校验后预览的能力，不能为看文件名单先下载数 GB 原文件。

### E. 恢复前确认

在下载、校验和兼容升级全部通过后出现，展示：

- 来源备份的内容时间与设备。
- 将恢复的角色、属性、历史、原文件数量及总量；可再次打开目录。
- 当前本机将被替换的角色与原文件数量；明确整份替换、不做合并。
- 最近恢复前副本会保留、占用空间、可切回；切回也会替换之后的编辑。
- “确认替换并恢复”为墨色动作，“先不恢复”为可返回的操作。

准备完成不自动执行覆盖。用户重新浏览目录后应有直接“返回恢复确认”的入口。确认摘要绑定 epoch/revision；这期间本机又保存了资料则刷新摘要重新确认。

### F. 完成与失败报告

备份完成：内容时间、创建者确认时间、实际耗时、完整范围、本次上传量、复用量、“查看这份备份”。

恢复完成：来源内容时间、本机开始/完成时间、实际恢复数量、检查结果、恢复前副本入口；用完整结果报告替代只弹一个短暂 toast。

失败：发生阶段、受影响的文件友好名称、可重试操作、旧备份/本机数据是否保持。不得在未确认回滚/恢复状态时声称“本机未改动”；处于启动修复时用“正在检查本机资料”。

## 4. 时间语义

| 字段 | 用户文案 | 规则 |
|---|---|---|
| snapshotCreatedAtUtc | 备份内容时间 | 已保存资料被固定的时间；主列表优先显示这个时间 |
| operationStartedAtUtc | 开始备份 / 开始恢复 | 本次操作时间，不用文件最后修改时间代替 |
| writerObservedCompletedAtUtc | 创建者确认云端完成 | 创建设备观测所有必需文件与 commit 上传确认的时间 |
| restoreCompletedAtUtc | 本机恢复完成 | 激活及健康检查完成后才记录 |
| activeElapsedMs | 实际处理用时 | 基于单调计时片段累计；暂停/跨重启缺失信息不可虚构 |
| discoveredAtUtc | 本机发现时间 | 可用于诊断，不能作为备份创建或上传完成时间 |

持久化 UTC，界面转本地时区；跨日期写明年月日，可在详情显示时区。创建者完成回执未同步时显示“完成时间未提供/待同步”，不能从云文件 mtime 推算。未来时间/设备时钟异常不作为覆盖和保留顺序依据。

## 5. 数据合同增补

### 5.1 与快照绑定的内容目录

新格式尚未上线，直接完善拟议 v3：新增不可变 `contents.json`，由同一 SQLite 快照派生，在 manifest 中记录文件名、字节数、SHA-256；与 DB、媒体一起验证上传后再发布 commit。

拟议字段：

```text
format = 1
snapshotId, schemaVersion
summary: roleCount, revisionCount, customAttributeCount, coverCount,
         assetCount, assetCountsByKind, originalFileCount, logicalDataBytes
roles[]: roleId, name, customAttributeNamesInOrder[], revisionCount,
         coverRelativePath?, assetIds[]
files[]: relativePath, objectId, roleIds[], assetId?, displayName, kind, bytes
```

目录只用于浏览；数据库仍是角色领域数据真值。目录名称取备份时的数据，不能查询当前本机角色表补名称。共享立绘可关联多个 roleIds。原文件显示名与内部 objectId 分开。恢复激活前根据数据库重算并核对目录/manifest，防止展示 A 内容、实际恢复 B 数据。

备份总量中的 logicalDataBytes = 数据库快照 + 不重复的逻辑原文件；上传量另包含内容目录等协议文件。计数和字节必须明确去重口径。内容索引设置长度/数量边界，列表分页，不一次生成数万行组件。

旧备份没有 contents.json 时，只下载该份 SQLite 到只读隔离环境派生目录；不能用当前本机资料补齐。状态写“正在读取旧版目录”；目录不能完整生成时，不伪装为空备份。

### 5.2 完成回执

创建者在 commit 已确认上传后，持久化本次确认时间；可附加发布不可变 `receipts/<snapshotId>/completed.json`，绑定 commitSha256、snapshotId、writerId、writerObservedCompletedAtUtc、可提供的处理时长。

回执是补充显示信息，不是恢复依赖，也不是循环地要求“回执本身上传后再改回执完成时间”。它同步失败不否定已经完整上传的备份；其他设备显示时间未知。回执不能覆盖/改写 commit，失配回执不可用于界面时间展示。

### 5.3 任务事件与计数

`BackupJobState` 增补：固定内容范围、阶段、起止时间、累计用时、currentItemRef、已确认/失败/复用数量、字节计数以及进度来源。

```text
ItemProgress: itemRef, state, attempt, completedBytes?, totalBytes?,
              measurement = nativeObserved | localMeasured | unknown
JobEvent: operationId, sequence, phase, itemRef?, state,
          observedAtUtc, errorCode?, counters?
```

不把内部路径或角色设定全文写进事件日志。友好名称通过任务绑定的 contents index 解析。事件按 sequence 防乱序，operationId + epoch 防过期回调；UI 每 250–500ms 节流一次，阶段/失败/最终结果立即更新。可访问性只播报阶段变化和必要里程碑，不逐字节朗读。

内容时间、事件、完成报告随任务持久化；页面重新进入能恢复状态。历史备份目录存在云端；本机失败和取消事件不自动当成已完成快照同步出去。

## 6. 交互原型范围

会话内原型使用示例数据，覆盖：总览、备份前范围、角色/文件目录、分页、文件信息、时间记录、上传及等待确认、失败重试、恢复下载、完整性检查、替换确认、完成报告。可通过预览设置切换流程阶段，并比较展开全部步骤/只显示当前步骤。

原型是审核工具，进度由演示状态驱动，没有连接真实 iCloud，没有下载/恢复用户资料。速度/剩余时间的真实采样合同写在本文件，不在演示中伪造为当前平台实际能力。

## 7. 增补验收

- V01 本机/快照目录统计与其固定数据库、媒体引用一致；重复属性和共享文件口径正确。
- V02 备份完成后本机重命名角色/资产、修改设定，历史目录和内容时间不变。
- V03 未下载媒体即可浏览全部角色/文件名；大目录分页且不撑爆内存。
- V04 完整范围、需传输量和复用量分开展示，上传进度分母不使用完整资料总量。
- V05 字节进度不可得时无虚假百分比/速度/ETA；传输 100% 仍会显示等待确认。
- V06 下载完成、校验完成、准备就绪和恢复完成各有独立状态，不提前跳成功。
- V07 返回重进、暂停重试、超时、后台重启后任务范围/时间/进度仍对应同一 operationId。
- V08 失败可定位友好文件名和阶段，重试不修改备份范围；目录失配在恢复前拒绝。
- V09 UTC/本地时区、跨日、完成回执缺失/失配、设备时钟异常有明确展示。
- V10 恢复确认摘要与当前 epoch/revision 一致；浏览目录后可直接返回确认。
- V11 完成报告保留数量、时间、检查结果；恢复前副本入口可发现。
- V12 明暗模式、320px 窄屏、大字、长文件名、键盘操作与读屏阶段播报可用。


## 摘要缓存对进度文案的影响

导入时预先计算摘要、后续备份命中有效索引的文件显示“复用已有文件”，不能计入“本次重新校验了 N 份原文件”。第一次为旧资料补算摘要时显示处理文件数/字节数和阶段，允许取消；真正上传/恢复的字节校验仍有独立状态。云端清单摘要一致不代替对象存在、上传完成与恢复时的内容检查。

恢复空间估算还需考虑本机尚未物化的 iCloud 文件缓存；原型中的固定空间数字是示例，不可直接作为生产算法或容量保证。


## 已确认账户级保留与恢复规则

同一 iCloud 账户合计保留最近 3 份完成备份，所有设备共享列表；文案为“账户合计保留最近 3 份”，设备名称只表示来源。按账户发布顺序显示正常历史，内容时间单独展示。文件上传完成但账户登记尚未确认时继续显示等待完成，不能插入第 4 条正常完成记录。

同步/物理清理延迟和旧版迁移残留单独表示状态及占用。损坏数据首版不部分恢复；内部保留最近 1 次恢复前副本并提供清理入口，均已获用户确认。创建者完成回执的时间取内容上传及账户登记全部成功之后，原始上传观察时间可单独保留。
