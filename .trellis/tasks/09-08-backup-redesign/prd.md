# 备份与恢复重设计

状态：**开发实现与本机自动验证已完成，真实设备及用户验收待完成**。实际证据见 `verification.md`；下方 Acceptance Criteria 作为完整发布验收清单，未以本机测试替代真机验收。

## Goal

让用户能够可靠保存和恢复完整角色资料；新备份失败不破坏旧备份，恢复失败不留下混合数据，用户能辨别等待同步与备份完成，并能在误恢复后找回恢复前资料。

## 已知约束

- 当前为本地优先的 OC 档案应用；SQLite schema 8。
- 范围包括角色资料、设定历史、自定义属性及顺序、立绘原图和全部资产原文件。
- 用户 2026-09-08 确认：**尚未统计数据量，按数 GB 设计**，资产含视频/音频。
- 延续 iOS/macOS、手动备份、整份恢复基线。用户要求先审查和重新设计，再由其审核。
- 现有格式 v1/v2 和已知无清单旧布局需保留迁移入口；不破坏用户云端旧槽。

## Requirements（产品规则已确认）

- R1 每份成功备份能独立恢复全部已保存资料及其引用文件；原文件字节不做有损变化。
- R2 未完整完成的新备份不会覆盖或删除先前可用备份；明确显示 pending/failed/completed。
- R3 根据内容复用未变化媒体，避免数 GB 资料每次全量重传；不将未被引用的弃用立绘放入新备份。
- R4 用户可以识别并选择不同时间、不同设备的备份；用户已确认同一 iCloud 账户合计保留最近 3 份已完成云端备份，来源设备不分配独立名额；异常/待确认任务不挤掉完整备份。
- R5 文件下载和数据库迁移均在覆盖前验证，未知格式、损坏、缺失、版本不兼容时明确拒绝。
- R6 恢复必须在准备完成后由用户确认；取消、离开页面、超时、重启都不能偷偷进入覆盖。
- R7 数据切换遇进程崩溃后，重新启动能回到完整旧数据或完整新数据；不自动清空故障库。
- R8 保留最近 1 份恢复前本地资料，支持用户确认后切回；提前告知空间占用。
- R9 同一应用的备份、恢复、清理不会互相覆盖；iPhone/Mac 并行备份不会争写一个槽。
- R10 支持合法零字节文档；严格区分缺失、未下载和真实内容损坏。
- R12 明确说明当前数据量、文件数、状态、等待原因和可恢复错误；不要求用户理解内部随机路径。

## 用户追加要求：全链路可视化（已明确）

2026-09-08，用户要求看到备份了哪些数据、备份时间、备份进度与恢复进度。

- R13 从总览进入每份备份的角色/文件目录，名称与统计固定在备份时刻。
- R14 备份前显示完整范围、本次需上传量和复用量；这些数字不得混用。
- R15 备份/恢复显示阶段、真实可测进度、当前文件、已完成数量、等待或失败原因。
- R16 显示内容时间、开始时间、确认完成时间和恢复时间；无法得知的时间不推算。
- R17 完成后提供可查看的结果报告；返回/重进和重试仍能看到同一任务的状态。
- R18 内容浏览不要求先下载所有媒体，且不会隐式改变整份备份/恢复范围。

以上可视化目标已由用户提出；用户随后回复“可以的”，已认可可视化原型的总体方向。详细索引合同及完整技术方案仍随实施设计审核，见 `visual-experience.md`。

- R19 文件导入时计算并缓存内容摘要；后续未变化媒体的备份减少重复全量读取，首次上传和恢复的实际字节校验不可省略。

## Acceptance Criteria

- [ ] AC01 在上传任一步失败，之前完成快照的所需字节不变，仍可完整恢复。
- [ ] AC02 原生本机写入完成但云端尚未确认时，UI 不显示备份完成。
- [ ] AC03 截断文件、同大小不同内容、缺失文件、manifest/DB 不一致均在本机切换前被拒绝。
- [ ] AC04 包含空文档、Unicode 名称、自定义属性重复名/顺序和多种资产的完整往返一致。
- [ ] AC05 只改角色文本/资产名称后，不重新上传未变化媒体原文件。
- [ ] AC06 每个恢复提交边界强制终止进程后，重启不会产生新库配旧文件等混合状态。
- [ ] AC07 准备失败或取消时本机保持原状；切换成功后清理失败不改变成功结果。
- [ ] AC08 返回、重进、重复点击、超时和迟到回调不会产生第二个相互竞争的写入任务。
- [ ] AC09 两台设备各自产生快照，能互相选择并恢复，不依赖一个共享 latest 文件。
- [ ] AC10 旧格式/schema 3–8 可验证迁移；较新/过旧/损坏数据有明确错误并保住本机。
- [ ] AC11 恢复前能看到空间要求，低空间/配额不足/账号切换不损坏旧资料。
- [ ] AC13 用户可找回上一次恢复前的本地资料；确认文案说明会替换此后的编辑。

- [ ] AC14 历史目录名称和数量不随本机后续编辑变化，且与该份快照内容一致。
- [ ] AC15 资料总量、实际需传量、复用量及本阶段完成量分别展示且计算正确。
- [ ] AC16 传输 100% 不冒充云端已确认；下载 100% 不冒充已恢复。
- [ ] AC17 等待、暂停、重试、离开/重进和进程重启后仍能追溯任务范围与进度。
- [ ] AC18 内容时间、开始和完成时间、来源设备、结果报告可查看；未知时间不伪造。
- [ ] AC19 大目录无需下载数 GB 媒体即可浏览；长名称、明暗模式和窄屏交互可用。

- [ ] AC20 摘要缓存正确处理改名、内容替换、旧文件补算、dataset 切换和失败；未变化备份减少媒体读取，大文件处理不在 UI isolate 持续计算。

## 当前决策汇总

用户已确认：

1. 首版专注 iCloud 备份与恢复，不提供手动备份文件导出/导入。
2. 全链路可视化：范围、历史目录、时间、进度、错误和结果报告。
3. 同一 iCloud 账户合计最近 3 份已完成备份，所有设备共享名额。
4. 损坏/缺失先重试，仍失败则提示用户选择其他有效备份；校验失败不覆盖本机，首版不做部分恢复。
5. 每台本机保留最近 1 次恢复前的数据，提供明确清理入口；下一次成功恢复后可清理更旧的内部副本。
6. 按数 GB 数据量设计。

技术方案已纳入用户提出的摘要预计算/缓存方向；算法采用 SHA-256，后续备份复用索引，实际上传/恢复仍校验字节。

不再把上述事项作为待确认产品问题。R11 / AC12（手动备份文件交换）已撤销，编号不复用。

技术修订：旧的每 writer 保留/清理规则撤销，writer 分路径仅防止文件名冲突；采用账户统一保留集合与跨设备安全引用保护。推荐以 CloudKit 私有账户目录条件更新协调现有 Documents 大文件，详见 `research/account-retention.md`。两端 Apple 工程已加入 CloudKit 能力；远程 schema 与签名配置尚未验证。

正常保留集合为 3 份；上传暂存、尚未物理删除的退休内容及兼容迁移残留会单独显示状态/占用，不承诺任意瞬间物理文件数量的硬上限。重要备份固定为额外第 4 份不纳入首版。

业务代码和本机自动验证已完成，后续为真实平台与用户验收，不需要重新询问已确认的产品规则。

设计在 `design.md`，交互在 `visual-experience.md`，执行步骤在 `implement.md`。
