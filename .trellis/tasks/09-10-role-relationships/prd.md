# OC 关系

## 背景

崽档目前每个 OC 是孤立的：只有固定字段、自定义属性、设定历史和资产。用户希望记录 OC 之间的关系（例如 A 和 B 是师徒），并在任一方的详情页里看到这条关系。

## 需求

1. 一条关系连接两个不同的已保存 OC。
2. 关系是**有向**的，用两段用户自填的文字描述：
   - 「A 是 B 的 ___」（例：师父）
   - 「B 是 A 的 ___」（例：徒弟）
   两段文字均可自由输入，不预置类型，也不做类型管理。
3. 同一对 OC 允许存在多条关系（师徒 + 恋人）。
4. 一个 OC 可以拥有任意多条关系；从 A 的详情页和 B 的详情页都能看到同一条关系，且措辞按各自视角显示。
5. 关系可以新增、修改（两段文字和对方 OC）、删除。
6. 关系只在编辑已保存的 OC 时可用，新建流程不含关系（与「资产」Tab 一致）。
7. 删除任意一方 OC 时，涉及它的关系全部随之删除。
8. 关系随整库快照进入备份；恢复旧备份（无关系表）后关系为空，不报错。
9. 不做关系备注、不做预置类型、不做关系图谱可视化。

## 验收标准

- 在 A 的详情页新增关系「A 是 B 的 师父 / B 是 A 的 徒弟」后：
  - A 的「关系」Tab 显示 B，文案「我是 TA 的 师父 · TA 是我的 徒弟」（或等价措辞）。
  - B 的「关系」Tab 显示 A，文案反向。
- 同一对 OC 可再新增第二条不同文字的关系。
- 选择对方 OC 时列表中不出现自己；库里没有其他 OC 时给出提示。
- 两段文字任一为空时不能保存。
- 修改后两端页面均实时更新；删除后两端均消失。
- 删除 OC 后其关系行为 0（外键级联）。
- schema 7/8 的旧库升级后原有角色、属性、历史、资产完好，且可以新建关系。
- schema 3–8 的旧备份仍可恢复，恢复后 `user_version` 为最新版本。
- `flutter analyze` 与 `flutter test` 全绿。
